## 보류한 기능

| 기능 | 왜 보류했나 | 할 때의 방향 | 언제 |
|---|---|---|---|
| 취소 규정 삭제 → **보관(소프트 삭제)** | 실제 삭제는 막는다. 공연(공개·작성 중·취소 모두)이 `cancel_policy_id`로 규정을 가리키고 논리 FK라, 지우면 공연 상세의 취소·환불 안내가 사라지고 깨진 참조가 남는다. 삭제가 없으면 규정이 쌓인다(개수 상한 없음, 공개 공연이 쓰는 규정은 고칠 수 없어 새로 만듦) | 행을 지우지 않고 `deleted_at`만 채운다(`SoftDeletableEntity`, `findBy…DeletedAtIsNull`). 보관한 규정은 목록·공연 등록 선택에서 빠지고, 이미 쓰는 공연에는 그대로 보인다. 그래서 "쓰는 공연이 있는가" 검사가 필요 없다. 기본 규정은 보관할 수 없다. 컬럼 추가(마이그레이션)와 명세(SLR-19~22)가 필요하다 | 판매자 화면에서 규정 목록이 불편해질 때 |
| 등급 삭제 API (`DELETE /api/v1/seller/performances/{performanceId}/grades/{gradeId}`) | 팀 문서(`api-spec` SLR-09·10)에는 등급 추가와 수정만 있고 삭제가 없다. 삭제가 없으면 잘못 만들었거나 안 쓰기로 한 등급이 판매자의 등급 목록에 남는다. 예매자에게는 영향이 없다(예매자 공연 상세는 구역에 지정된 등급만 가져온다). 남은 등급은 SLR-10으로 이름·가격을 고쳐 다른 등급으로 쓸 수 있다 | `api-spec`에 먼저 넣고 팀과 맞춘 뒤 만든다. 삭제 조건 후보: 공연이 취소되지 않았고, 좌석을 만들기 전(`locked`가 false)이고, 어느 구역도 그 등급을 지정하지 않았을 때만. 새 에러 코드가 필요하다(예: 구역이 쓰는 등급이면 409). **확인할 것**: 취소된 회차의 좌석(`schedule_seat`)은 만들 때 복사한 등급 번호를 계속 가지므로(취소 이력), `locked`가 false여도 그런 좌석이 가리키는 등급을 지우면 깨진 참조가 남는다. 이 경우를 막거나 취소 규정처럼 보관(소프트 삭제)으로 하는 방법을 정해야 한다 | 판매자가 등급을 지우고 싶다는 요구가 생기거나 등급 관리 화면을 설계할 때 |
